# Mrs. English Ver.3 — 第1段階

既存アプリとは独立した、iPhone横画面向け静的PWAです。納品された画像・JSON・フォントは変更せず参照しています。

## 起動

Node.js 24で確認済みです。ランタイムに外部サービスやAPIキーは必要ありません。

```sh
cd /workspace/Mrs.English_ver3
npm ci
npm run build
npm run preview
```

HTTPサーバーは4173番ポートで起動します。制作中は `npm run dev` でも起動できます。オフライン動作の検証は `build` 後の `preview` を使用してください。

`dist/` をHTTPSの静的ホスティングへ配置できます。全パスは相対参照のためサブディレクトリ配信にも対応します。iPhoneのSafariで開き「ホーム画面に追加」で起動してください。PWAインストール・サービスワーカーにはHTTPS（ローカル検証時はlocalhost）が必要です。iOSの向きロックは保証されないため、縦向き時は横向き案内を表示します。

## 構成

- `src/app.js`: 画面遷移。
- `src/layout.js`: 全画面共通の背景分離・セーフエリア・表示領域への均一拡縮。
- `src/home-hud.js`: ホーム上下の9-sliceバー、内容と操作範囲の幅追従。
- `src/screens.js`: 画面別の動的な写真・選択状態・入力・タップ領域。
- `src/components.js`: 納品画像・独立SVG文字・ボタン・9-slice。
- `src/profile.js`: 保存データの検証とlocalStorage例外処理。
- `public/backgrounds/`: 提供ZIPの元画像。`layouts/external_backgrounds.json` の対応を維持。
- `public/sw.js`: オフラインキャッシュ。ビルド時に素材とコードからキャッシュ版を生成。
- `qa/browser/`: 実際のブラウザーキャプチャ、モックアップとの比較、機能検証結果。

初回はタイトル→ニックネーム→推し→背景→ホーム。2回目以降もタイトルを表示し、タップ後はホームへ進みます。保存キーは `mrsEnglishV3.profile`。学習・ガチャ・カード・課金は実装していません。各ホームボタンの遷移先は空白画面とホームへ戻るボタンのみです。

## 検証

起動したpreviewサーバーに対して実行します。

```sh
npm test
npm run test:layout
npm run test:home
python3 scripts/compare.py
```

ブラウザーテストはPlaywrightと `/usr/bin/chromium` を使用します。別環境では `CHROMIUM_PATH` と必要なら `TEST_URL` を指定してください。画像比較だけはPythonのPillowが必要です。

比較ページは開発サーバー上の `qa/browser/index.html` にあります。制作キットのモックアップやQA画像は本番ビルドへ収録していません。

## 共通の画面レイアウト

写真背景は `#scene-background` として画面全体に `object-fit: cover` で表示します。縦横比を保持して中央トリミングし、ノッチやホームインジケーターの領域まで写真で埋めます。写真をセーフエリア内のUIキャンバスへ再配置しないでください。画面全体を引き伸ばしたり、2枚の写真で周辺だけを継ぎ足したりしていません。

照合用 `photo_plate.png` はUI除去跡を既存のUIで隠す前提の画像であり、独立coverにすると除去跡が露出します。そのため背景だけは提供済み元写真に統一します。タイトル・ニックネームは `assets/photos/top_original.jpg`、推し・背景選択は `backgrounds/bg-01.jpg`、ホームは保存済み背景です。設定画面では読みやすさを保つ暗色オーバーレイを重ねます。写真ファイル自体、完成モックアップ、装飾PNG、JSONの座標は変更しません。元写真の構図は生成済み照合写真とは異なります。

UIは独立した1844×853の `#stage` に置き、セーフエリアとvisualViewportの交差領域内で `min(width/1844, height/853)` によって均一拡縮します。PNG、文字、入力、タップ範囲は同一変換で配置され、従来の配置データを変更しません。ソフトキーボードで見える範囲が狭くなった場合も同じ処理を利用します。

将来の画面も同じ `createLayout` / `sceneBackground` を使用してください。現在のJSONでは `(x,y)=(0,0)`、`z=0`、1844×853の画像要素が背景です。`isSceneBackground` でUIから分離されるため、各画面で独自の背景リサイズを追加する必要はありません。ホームの背景選択も、この全画面背景の画像を切り替えます。仮の空白画面は引き続き写真を表示しません。

ホームの上下UIは独立したHUDです。従来のuniform scaleを高さ・文字・アイコンへ保持し、キャンバスを安全領域全体へ拡張して、上部バーを上端、下部メニューを下端へ固定します。各枠は元JSONの9-slice境界（上18・右20・下17・左20）で背景と縁だけを横に延長し、文字やアイコンの幅・高さは変えません。タップ範囲も延長した枠へ追従します。初期設定画面のレイアウト・背景・保存処理には適用しません。

下部メニューは下のセーフエリアを最大8 CSS pxだけ利用し、端末下端に近づけています。下端には最低14 CSS pxの空間を残します（通常の下21pxのiPhoneでは7px下へ移動）。元から下インセットが14px以下の場合は移動しません。ボタン・文字・アイコン・操作範囲を同じ量だけ移動し、高さと上部UIは維持します。ホームだけ親のoverflowを許可し、セーフエリアを越えた部分も切れずにタップ可能にしています。`qa/footer-offset/` がこの位置調整後のキャプチャです。

`qa/home-width/index.html` にホーム上下UIの調整前後があります。代表的な幅基準のiPhone横画面で、セーフエリア幅に対する占有率は上部約89.5%→100%、下部約92.2%→100%です。参照のSuperStar画像は未添付のため、直接の比較は未実施です。幅・高さの異なる6条件（片側のみのノッチ余白とSafariの狭い表示領域を含む）で端の操作も確認しています。

`qa/layout/index.html` に修正前後および横画面サイズ別のキャプチャがあります。844×390、852×393、932×430、812×375、1844×853の5サイズ×5画面で、背景がviewport全体を覆うこと、UIのX/Y拡大率が等しいこと、セーフエリア内に収まることを検証しています。セーフエリアはChromium上でCSS矩形として模擬したもので、実機Safariの検証とは区別します。

## 残る確認事項

- iPhone実機のSafari、ノッチのセーフエリア、ソフトキーボード、PWAインストールは未検証です。844×390と縮小表示領域はChromiumで確認しています。
- 背景選択・ホームの写真は、モックアップの生成済み比較用写真ではなく、提供された22枚の元写真を使用しています。特にbg-01は構図が異なり、元写真の文字や人物位置も異なります。画像を改変・生成せず、中央coverで表示しています。
- 選択を他の推しへ移した状態は新たな承認モックアップがなく、納品フレームを9-sliceで適用しています。納品の写真レイヤー・人物切り抜きに、元の選択枠の淡いシアンの光が一部残っており、未選択の大森元貴カード付近に小さく見える場合があります。
- 固定文字には納品の限定フォントを使用しています。任意のニックネームと変更後のプレビュー番号はフォールバックで表示します。未フォーカス入力欄に見本の固定カーソルは重ねません。
- 公開は `.github/workflows/pages.yml` がmainへのpushで実行します。iPhone実機検証は未実施です。

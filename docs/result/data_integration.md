# データ連携・表示責務

Workでは公開リポジトリを読んでいない。以下はアダプターが必要な概念項目であり、既存の保存キー/型/関数があると断定しない。結果表示は既存の確定済み結果を読むだけ。カード・コイン・最高スコアの管理を作り直さない。

必要情報：stageId、categoryId/文法番号/短縮名、difficulty、backgroundIdとクロップ位置、questionCount=10、correctCount、maxCombo、totalActiveAnswerMsと対象回答数、開始時deckSnapshotのカード個体ID/画像/フレーム、発動スキル情報、基本/速度/コンボ/スキル純増/デッキの内訳raw、確定totalScore、獲得rewardCoins、dailyMultiplier、報酬付与済みtransactionId、既存最高スコア記録。

平均時間は原則全10回答のアクティブ時間合計÷回答数、停止/背景化/回答後待機を除く。誤答も含む。既存定義が異なれば差分を報告し無断変更しない。未記録値を架空の0秒にせず「—」で表示。正答率は正解数÷10×100。スキル保護を正解数に含めない。

## 評価

10 PERFECT!! / 9 EXCELLENT! / 7〜8 GREAT! / 5〜6 GOOD! / 0〜4 NICE TRY!。点数による判定ではない。0〜10以外や未完了は通常の完了結果として扱わず状態を調べる。

## 二重計上防止

基本/速度をスキル適用前、スキルを純増分として表示する。既存内訳がスキル込みなら計算側の実際の確定内訳から適用前/純増を読み分ける。率を推測して逆算しない。情報不足は既存計算関数に表示用の内訳出力を追加する最小案を報告。スキル込み基本点へさらにスキル点を足さない。COMBO SUPPORTは直接加点しない。デッキ点はステージ終了時1回、Rコインは合計点と別。

## 整数の表示

採点/端数処理は既存実装を調査して優先。表示のために採点を変更しない。raw値を保持し、表示5項目の合計が確定totalScoreと一致するよう表示専用配分を行う。非負項目の合計rawを四捨五入する既存仕様なら、各項目を切捨てて、差分を小数部の大きい順へ1点ずつ配分。同率は基本→速度→コンボ→スキル→デッキの固定順。例raw=[1000.4,500.4,50.4,0,62.4]、確定1614なら表示[1001,501,50,0,62]。実値・報酬を変更しない。既存総点がこの方法の前提を満たさない場合は差を隠して押し込まず原因/既存丸めを調査。各項目独立四捨五入による不一致は禁止。表示は整数3桁区切り、正答率と秒数は成績の表示形式に従う。

モックアップ例：NORMAL、10正解、各12秒、総パワー6270、スコア+5%と速度+20%の仮定で15000+4500+2750+1650+627=24527。報酬450×2=900。画像のサンプル倍率/カード/数字で既存データを上書きしない。

## 保存/報酬

結果表示開始前に既存の完了精算が成功した確定結果を取得する。既存側にない場合は必要な接続点を提案し、表示コンポーネント自身へ加算処理を置かない。既存のstageId/transactionIdによる一回限り精算と保存を調べる。表示/スキップ/音/animationend/再表示/戻るボタンは残高を変更しない。精算途中/失敗ならリトライ状態を表示、架空の受領済み結果を見せない。再読込は同じ確定結果を読む。
デイリー2倍は精算時に確定した倍率を表示。リザルト閲覧中の時刻変更で再判定しない。highestScoreの保存も既存完了処理を優先。

## 遷移

もう一回：categoryId+difficultyを既存の開始処理へ渡し、新stageIdと重複なし新しい問題抽出/順序を作る。カテゴリに10問しかなければ同じ10問の順序替えでよい。終了結果を再開しない。背景は新ステージの既存抽選仕様に従う。
ステージ選択：既存の文法・難易度選択画面へ。内部名READYでもUIは「ステージ選択」。ホーム：既存TOPルートへ。URL/ファイル名は推測しない。遷移中はボタンをロック、古い演出と音とリスナーを解除。

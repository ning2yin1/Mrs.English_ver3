# Codex実装指示書

## 目的と範囲

既存Mrs. English Ver.3の仮リザルトを、承認済み3画像と同じ雰囲気・配置の表示へ置き換える。約3.8秒のスコア演出、5評価、通常結果、日本語3ボタンを実装する。今回のZIP自体にはアプリ実装は含まない。
TOP/Collection/Inventory/Shop/ガチャ/問題データ/プレイ採点を再設計しない。保存データ消去、カード初期化、コインの重複管理は禁止。

## 作業前のコード調査

必ず既存リポジトリを調査し、次の実ファイル/関数/保存先を報告する：
1. ステージ完了、最終スコアと未丸め内訳、スキル適用前/純増分、既存丸め。
2. 正解数/最大コンボ/回答時間の記録と平均時間の定義。
3. 開始時装備snapshot・背景IDとクロップ位置。現在の装備を取り直さない。
4. Rコイン精算・日次2倍・精算済みID・最高スコア保存と失敗時復旧。
5. 文法選択/ステージ開始/TOPへの既存ルートと共通UI素材/フォント。
6. PWAキャッシュ更新方式と結果再表示/複数タブ時の扱い。
Work側では公開コードは確認していない。名前が似た新ストアを推測で作らない。必要情報が欠けていれば、既存の確定処理に表示用出力を追加する最小案を報告する。

design_spec.md → data_integration.md → animation_spec.md → asset_manifest.md → quality_report.md。

## 実装順

1. 既存結果を読む薄いアダプターを作り、実データと表示5内訳を照合。画像の例24527/900を固定値にしない。
2. 既存の同一UI画像を優先し、resultの独立コンポーネント/名前空間へ配置。新規画像はassets/result/ranksとfx。reusedは既存画像の無変更コピーなので既にあれば参照再利用。
3. HTMLで全数字/文字/操作を描画。評価5種類のみ特殊装飾PNGを切替。画像にはaria-hidden、同じ評価文言をDOMで読み上げられるようにする。カードも既存描画部品。
4. 基準1536×710で通常画面を参照画像と比較。次に667×375/844×390の安全領域、タップ44CSSpx、桁数/長い文法名を確認。
5. 確定データを変更しない演出コントローラーを接続。スキップ/中断/動きを減らす設定と任意の音同期イベントを実装。
6. もう一回は同一文法/難易度で既存開始処理に接続。ステージ選択/ホームは既存ルートへ。ボタン連打/スキップ同一ジェスチャーを抑止。
7. 二重付与/保存互換性/既存画面の回帰と下記項目を確認し、追加/更新ファイルを報告。

## 対象ファイルの扱い

キットの追加先：assets/result/、docs/result/、references/result/、README_RESULT_KIT.md、file_manifest.csv。余分な親フォルダなし。既に同名があれば差分を見て上書きしない。
実アプリで更新する可能性があるのは、既存仮リザルト表示・完了結果の受渡し・既存ルート接続・PWAキャッシュ。実パスは未確認なのでこの文書で架空ファイル名を確定しない。保存/採点/報酬の本体は既存処理を優先し、必要な最小の表示内訳出力以外は変更しない。

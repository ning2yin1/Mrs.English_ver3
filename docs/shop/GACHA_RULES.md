# 商品・抽選・カード付与の仕様

仕様の正本はdata/shop/catalog.json。Rコインのみ使用しダイヤは表示だけ。プレミアム商品・課金商品・ダイヤ消費は作らない。

|SKU|枚数|価格|確定枠|
|---|---:|---:|---|
|normal_1|1|1000 R|なし|
|normal_5|5|5000 R|なし|
|normal_10|10|10000 R|10枚目のみS/R|
|welcome_10|10|0 R|10枚目のみS/R。初期設定完了・正式受取未済の1回だけ|

通常抽選はR1/S9/A25/B30/C35（計100）。整数0..99を一様に取り、0=R、1..9=S、10..34=A、35..64=B、65..99=C。10枚パックのindex9だけは専用表R10/S90（0..9=R、10..99=S）。index0..8は通常表、5枚は全5枚が通常表。最初から10枚すべてをS以上抽選にしない。無料10枚も通常10枚と同じ表と演出。

乱数は購入処理でだけ生成する。crypto.getRandomValues等の乱数源を用い、100/カードプール長への剰余偏りを避けるrejection samplingで範囲整数を得る。次に選ばれたランクの有効catalogIdから1枚を抽選。ランク内選択は未指定なので、本キットでは「既存カタログ内の同ランクカードを均等・復元抽選」を明示した初期方針とする。人物別の均等化や、所持済み除外は行わない。後で重みを調整できるようランク表とランク内プール設定を分離する。

既存catalog全件を使用し、QA画像に出る8種類だけを抽選プールにしない。写真/ランク枠は既存参照。必要ランクのプールが空/不正なら購入確定を拒否し、別ランクへ勝手に置換しない。

同じcatalogIdを何度引いてもよい。新しい各個体に別instanceId（例purchase:<purchaseId>:<index>）を付け、level=1で追加する。既存個体のlevel・acquiredAt・編成を変更せず、同一画像だからといって既存個体を上書きしない。

Collectionの種類別quantityは当選個数分加算。既存の種類別初回入手日は不変、未所持種類だけ今回日時を初回日とする。新規個体のacquiredAtは今回日時であり、種類別の初回日とは別。Inventoryは同じ所有台帳と新規個体を参照して即時表示。2画面分のカードを二重に付与しない。既存deckは保持し、自動編成しない。

抽選は購入commit前に1回だけ行い、順序・catalogId・rarity・instanceIdをレシートへ保存する。画面再表示、めくり、スキップ、結果へ復帰で再抽選してはならない。保証ラベルはindex9だけ。途中でカタログ定義が更新されても永続レシートの結果を引き直さない。

# Codex向け実装指示

今回は素材/設計のみ。実装はこのキットを渡された次工程で行う。デザインを変えず、共通素材を使い、画面背景1枚+透明ボタン方式やCSSによるボタン/パネルの独自描き直しは禁止。

## 既存への接続

既存Shopボタンのルートを現行コードから読み取り、新しいShop画面へ最小接続する。Shop専用renderer/controller/FX/取引アダプターを専用フォルダ（例src/shop）へ分離。既存TOP/Collection/InventoryのUIファイル・配置・写真/枠・初期設定を変更しない。共有素材の上書きは不要。カード/コインAPIはPURCHASE_AND_SAVEの規則で既存を優先する。

## 6画面

1. Shop：1/5/10枚のカードパック。無料未受領なら案内を表示。受領済みなら無料案内だけ非表示とし、商品パネル座標は動かさない。価格はcatalog設定から表示。
2. 確認：選択SKUを中央へ、枚数/特典/価格/残高/購入後残高を更新。無料は価格0、「無料で受け取る」、残高不変。1/5枚では保証ラベル/10枚目の保証文を非表示。残高不足は購入ボタンを同じ青画像opacity.45、「Rコイン不足」、disabled、購入後残高は「—」。キャンセル/閉じるは保存変更なし。
3. 開封待機：永続commit済みレシートだけを渡す。通常と無料で同じパック画像/演出。タップは演出開始だけ。
4. 公開前：原本裏面、現在index/total、total数のドット。1枚なら1/1、5枚1/5、10枚1/10。保証文はtotal10のSKUだけ。スキップは付与済みの同じ結果へ。
5. 公開後：固定結果のカード/枠/名前/rarity。Rは承認金色、Sは指定紫金。次へは次の裏面、最後はラベル「結果を見る」で結果一覧へ。待機中の二重タップでindexを飛ばさない。
6. 結果：receipt.results順で最大10枚。同じ画像を複数回引いても別個体として表示。保証ラベルはindex9だけ。OKでShop、Inventoryボタンで既存Inventory。どちらも再付与しない。

## 動的要素と文字

タイトル/価格/残高/枚数/カード名/ランク/ボタン名/進行状況は独立DOM文字。写真・枠・カード裏面は既存画像。パック本体・枚数円形バッジ・数値を別にする。演出は独立alpha PNGを変形し、カードに直接焼き込まない。フォント・座標・transform-originはJSONとLAYOUTを守る。

## 保存と演出

演出controllerはpurchaseIdと固定resultsを受け取り、購入/乱数/付与APIを呼ばない。購入serviceがcommitと投影完了を確認してからcontrollerへ渡す。リロード時はpending取引復旧を先に完了し、その後に表示する。タイミングを変えてもカードや金額が変わってはならない。

素材読込・decodeを演出前に行う。画像不足時に似た写真や一般アイコンへ置換しない。Safari実機・セーフエリア・低負荷/動き低減・保存容量不足・二重タップ・途中終了をCHECKLISTで確認する。QAの全画素一致はPillow条件であり、実装後のDOM/保存/操作の検証とは別。

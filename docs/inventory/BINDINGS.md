# 動的表示の結び付け

JSON内の10枚・数値・名前・selected状態はQAスナップショットです。以下をデータから計算し、画面画像に焼き込まないでください。

|表示|データ元/計算|
|---|---|
|カード画像/名前/レアリティ|所有instance.catalogId → 既存Collection catalog|
|個体レベル|InventoryのinstanceId別保存値|
|上限|rarity別R50/S40/A30/B20/C10|
|能力値|catalogId別定義と個体level。例はbasePower+(level−1)×powerPerLevel|
|デッキ総合力|編成中3個体の能力値合計。編集中はdraftDeckの合計|
|スキル名/効果|catalogId別skillId → balance定義。人物名やレアリティだけで固定しない|
|所持枚数|既存所持台帳に紐づく有効個体数。Collectionの枚数と一致|
|編成ラベル|draftDeckまたは確定deck内のinstanceIdの位置|
|Rコイン残高|既存アプリの残高API/保存元。別の残高台帳を作らない|
|強化後レベル|上限未満ならlevel+1|
|強化後能力値|同じ定義をnextLevelへ適用|
|必要コイン|balanceのコスト定義を現在levelへ適用|
|強化後コイン|currentWallet−cost。上限/不足時は確定処理しない|

QAデッキはdev-01/dev-03/dev-06の3個体。5200+4150+3100=12450。強化例はRのLv12→13、5200→5350、費用500、9979−500=9479。レアリティRのままです。

メインでカードをタップするとその個体を強化対象として選択し、カード強化ボタンから開きます。対象未選択なら編成1枠目を既定対象にし、未所持の架空カードを作らない。空デッキなら最初の所持個体、全所持0枚なら強化操作を無効にする。空のデータ時にQAカードを自動表示して埋めない。

編成画面は現在選択した枠のカードを右上へ表示します。候補を選ぶとdraftDeckのその枠だけ更新し、右上・発光・ラベル・総合力を同じdraftから再描画。別枠に同じinstanceIdがあれば候補を無効化する。同じcatalogIdでも別instanceIdなら編成可能。QA例の薄暗い「ほかの枠で編成中」と、選択中の青発光を取り違えない。

# 開発用10枚の取扱い

`data/inventory/dev_seed.example.json` は仕様・QA用のデータ例です。キットの展開だけではカードもコインも配布されません。将来Codexが明示的な開発モードで使う処理を実装するための資料です。

- enabledByDefault=false / developmentOnly=true。正式ビルドは無効を既定にし、1つの設定で外せる構造にする。URLだけで本番に配布できる裏口を作らない。
- 既存写真10枚、R2/S2/A2/B2/C2。画像は再収録せず既存catalogId/パスへ接続。具体的な個体ID・レベルはJSON、能力/スキルはcard_definitions.example.json。初期3枚はR大森/S若井/A藤澤で総合力12450のQA例。
- 配布は既存所有が完全に0枚の場合に限定。1枚でもあれば自動配布・上書き・デッキ/レベル/残高のリセットをしない。未完成の既存デッキも勝手に置き換えない。
- grantId=inventory-dev-seed-v1と決定的instanceIdを使用し、適用済みIDと個体の両方を確認して一度だけ配布。途中失敗は同じIDの再適用で重複しないようにし、既存所有への結合は共通付与APIを使う。開発時でもCollectionとInventoryに別々の10枚を作らない。
- 所有0枚で初回テスト付与に成功した場合だけ、JSONの3個体を初期デッキにできる。既存編成があれば維持。
- qaWalletR=9979は画像比較用の残高スナップショットで、開発用カード配布と同時に実残高へ書き込まない。強化検証にコインが必要なら既存の開発テスト用残高機構を別途明示的に利用し、本番残高を勝手に設定しない。
- firstAcquiredAtはQA撮影例。開発配布の実処理では最初に付与した時刻を1回だけ保存し、再実行で変更しない。正式な所持済みカードの日付へこの例の日付を書き込まない。

正式版の「初期設定完了後の無料10枚パック」は後日Shopで実装する別の付与イベントです。開発grantIdと正式packClaimIdを共用しない。開発用付与で正式パックを受取済みにしない/逆も同様。開発用データを正式配布履歴へ変換しない。今回はShopや初期設定への導線追加、配布/抽選コードの制作は含めません。

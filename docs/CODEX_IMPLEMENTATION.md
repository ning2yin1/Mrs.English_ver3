# Mrs. English Ver.3 — Codex implementation instructions

## 今回作る範囲

iPhone横画面用の、タイトル→初回設定3画面→ホームまでの操作可能なUIを実装してください。完成モックアップ5枚を見た目の基準とし、納品画像素材を優先使用します。学習問題、ガチャ、課金、ゲーム本体は対象外です。ホームから先は仮画面とホームへ戻る操作だけにしてください。

この指示書は実装担当への引き継ぎです。キット作成時点ではゲーム本体を実装していません。

## デザインとデータの優先順位

1. `mockups/*.png` がユーザー決定版の見た目。
2. `layouts/screen_index.json` が各画面の入口。
3. 新規4画面は `layouts/title.json`、`nickname.json`、`member.json`、`background.json` を使用。
4. ホームは `home_approved/spec/home_layout.json`、元のPNG、元の文字・配置仕様を使用。これらは承認済みで変更しない。
5. 透明素材の一覧と比較は `qa/`、既存ホーム分は `home_approved/qa/` を参照。

ホームJSONの画像パスは `home_approved/` を基準に解決してください。新規4画面JSONの画像パスはキットのルートを基準に解決します。パスの基準を混ぜないでください。

## 画像の使い方

- 紫バー、青い決定ボタン、入力枠、カード枠、背景選択枠、装飾パネル、Ready枠はPNGをそのまま配置。
- CSSで似たグラデーション・角丸・枠を描いて置き換えない。
- 名前、数値、タイトル、手順番号、決定、SELECTED、TAP TO START、Ver.3、サムネイル番号は独立した文字要素。
- ロゴは固定のブランド装飾として `assets/title/title_logo.png` を使用。ロゴ内のブランド表記は固定アートです。
- アイコンは `assets/icons/` またはホームの元アイコンを使用し、一般的なアイコンライブラリに置き換えない。
- 写真、枠、文字、アイコン、操作領域を別レイヤーにし、中央を覆う一枚の操作不能なUI画像にしない。
- `mockups/` と `qa/*/reconstructed.png` は参照専用。実際の画面として貼らない。

## 文字の位置とフォント

新規4画面は、モックアップのラベルを輪郭化した限定フォントを `assets/fonts/` に収録しています。JSONに表示文字、フォントパス、64px emでの字形の実寸境界を記録しています。フォントの行ボックスと目に見える字の位置は一致しないため、`glyph_bbox_at_font_size_64` を基準に文字のインク領域を配置してください。

同じ文字を画像ラベルとして切り出して配置しないでください。HTMLの文字、または独立したSVGのtext要素として表示できます。背景写真と文字は合成せず、別々に保ちます。

収録文字はラベルに必要な文字だけです。任意のニックネームや変更後の文章が収録外の文字を含む場合は、行全体を端末の日本語サンセリフなどへフォールバックしてください。収録文字だけが別の形になる混在を避けます。フォントの輪郭化に伴う薄い影・発光・アンチエイリアスの差は検証結果を参照してください。

## 初回と再起動

localStorageキー案：`mrsEnglishV3.profile`。保存するJSONの例：

```json
{
  "version": 3,
  "nickname": "Nene",
  "memberId": "motoki",
  "backgroundId": "bg-01",
  "setupComplete": true
}
```

- タイトルは毎回表示し、画面タップで分岐。
- 有効な設定が保存済みならタイトル→ホーム。
- 未設定・不完全・不正なデータならタイトル→ニックネーム設定。
- ニックネーム確定→推し選択→背景選択の順で進み、最後の決定でsetupCompleteをtrueにしてホームへ。
- 入力中・選択中は下書きとして扱い、戻る操作で入力内容を保持。
- memberIdはmotoki／hiroto／ryoka、backgroundIdはbg-01〜bg-22の範囲を検証。
- ニックネームは空白を除去して空欄を防ぎ、12文字を上限とする案をJSONに記載。保存・読み込みの例外を処理。
- localStorageが利用できない場合は、その起動中のメモリに保持し、保存できないことを利用者に伝える。

## 画面別の操作

### タイトル

タイトル写真レイヤー、透過ロゴ、TAP帯、文字を順に重ねる。全画面タップの対象はタイトルだけに限定する。点滅を加える場合もTAP文字の不透明度程度とし、ロゴや写真の描き直しは行わない。

### ニックネーム

写真レイヤー→半透明パネル→入力枠→入力文字・案内→決定ボタン・矢印。静止モックアップはカーソルが表示され、キーボードを開く前の見本です。実機はinput要素で入力し、フォーカス中のカーソルは原則ネイティブ入力に任せます。静止見本のinput_caretを重ねて二重に表示しないでください。

横画面のキーボード表示中は入力欄と決定操作が届くよう、表示可能領域の変化に追従させます。通常状態のデザインは基準座標を維持します。

### 推し選択

左から大森元貴、若井滉斗、藤澤涼架。人物写真は `assets/photos/`、枠は `assets/member/`、名前は文字、チェックは別アイコンです。

完成見本はmotokiが選択中です。選択状態はデータで持ち、1人だけに選択枠とチェック、SELECTEDを表示します。未選択枠も独立素材を用意しています。他の人物を選択した状態の新しいモックアップは作っていないため、素材の同じ縁・厚みを保持して適用してください。カード幅を変える必要がある場合は下記の9-slice方針を使用し、画像全体を縦横別倍率で引き伸ばさないでください。人物写真は枠の内側で縦横比を維持してcover表示します。

### 背景選択

見本のサムネイル配置は6・5・6・5枚の4段で、各段の幅が異なります。JSONの22個の実測領域を使い、均一グリッドへ勝手に変更しないでください。

元写真22枚は別途受領します。`layouts/external_backgrounds.json` に元ファイル名とbg-IDを記載しています。`assets/photos/background_tile_*.png` と背景プレビューは照合用の小さな写真素材です。元データ受領後はその写真からサムネイルを生成し、同じ領域へ収めます。モックアップに描かれた写真と番号が元データの順番どおりでない箇所を、誤った本番マッピングとして固定しないでください。

写真番号、チェック、選択枠、右のプレビュー、01 / 22の表示を別々に更新します。選択枠はサムネイルへ追従。決定で選択したbg-IDを保存し、ホームの写真を変更します。ホームに小さいサムネイルを引き伸ばして使わないでください。

### ホーム

元のホームの素材・位置・ボタン幅・ラベル配置を維持します。選んだ背景だけを切り替えます。Inventory／Collection／Mission／Shop／Ready、Menu、プレイヤー領域は元JSONのタップ範囲を使用。各仮画面にはホームへ戻る操作を付けます。中央にはバナー、挨拶、進捗カード、別のPLAYボタンを追加しません。

## 拡縮と9-slice

基準は1844×853px。セーフエリアを引いた矩形の中に、全画面を `min(safeWidth/1844,safeHeight/853)` で均一拡縮し、中央に置きます。座標・写真・タップ領域にも同じ変換を掛けます。

通常の全画面拡縮ではPNGを9-sliceへ分解する必要はありません。選択枠の追従など、枠だけを異なる幅へ合わせる場合の候補値は `layouts/selection_frame_rules.json` に記載しています。角・光の厚みを保持し、中心は透過、横辺・縦辺だけを伸縮させます。これらの別サイズ状態は新しい完成モックアップと照合した状態ではないため、Codex側で初期状態と他の選択状態をそれぞれ目視確認してください。

## 写真レイヤーと検証

photo_plate.pngは、完成モックアップからUIを分離するための比較用写真レイヤーです。元UIに隠れていた部分は補間・解析しています。元の撮影写真そのものとして扱わないでください。タイトル用に元のTOP.jpgを `assets/photos/top_original.jpg` として同梱しています。これへ直接差し替えると、生成済み完成モックアップとトリミング等が完全一致しない場合があります。

実装後に、初期表示を各mockupと比較し、ボタンの厚み、人物の見え方、フォント位置、セーフエリアを確認します。入力・選択・保存・2回目の起動分岐・全メニューの往復を確認してください。素材生成段階の検証と、ブラウザーやiPhoneでの表示確認は区別してください。
